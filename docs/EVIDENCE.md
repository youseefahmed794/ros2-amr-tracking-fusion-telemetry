# Saved evidence and publication scope

Artifacts under `experiments`, `experiments_bias_v2`, `experiments_bias_v3`, `results`, and `release` are historical, copied from the original project. Dates, source hashes inside manifests, and test counts describe those runs, not a new validation pass. The source hash entries in historical manifests may refer to old source states. New candidate hashes are recorded separately during preparation.

Retained evidence includes all three short experiment matrices (including the rejected prototype), per-trial CSVs, aggregate summaries, plots and representative compressed traces; the baseline and final benchmark; final and prototype long-run metrics/checks/manifests/plots; baseline/prototype source snapshots; two final and two prototype 240-second ROS traces; final saved test XML; timing JSON/CSV; and host WebSocket, RViz review and Gazebo summaries. No unfavorable metric rows were filtered out.

Two full offline `long-runs/traces.npz` archives (final and prototype, approximately 52 MB each) are omitted. Generate final offline traces with `scripts/validate_gyro_bias.py --output /tmp/amr-bias-new`. Prototype sources are retained for interpretation, but the current script reproduces the final implementation. The rejected prototype is not a supported alternate installation. Its complete archive remains in the original project.

Raw process/build logs, old environment/authentication diagnostics, redundant release copies, source checksum files for excluded historical trees, and superseded narrative validation reports are excluded. The original project remains intact. The publication copy retains final saved CTest/JUnit XML as historical execution evidence; XML can include machine names and absolute paths, which are environment metadata rather than current installation instructions.

References: the gyro model cites [Kalibr](https://github.com/ethz-asl/kalibr/wiki/IMU-Noise-Model) and [NASA](https://ntrs.nasa.gov/api/citations/20120010515/downloads/20120010515.pdf). Gazebo configuration follows the [DiffDrive](https://gazebosim.org/docs/harmonic/moving_robot/), [sensors](https://gazebosim.org/docs/harmonic/sensors/), and [ROS integration](https://gazebosim.org/docs/harmonic/ros2_integration/) references. The saved executor comparison is consistent with reported [rclpy timing issues](https://github.com/ros2/rclpy/issues/1223), without establishing their cause here.
